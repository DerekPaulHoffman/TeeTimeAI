# Simulator support in the existing responder

Simulator demand uses the sole ten-minute course-support dispatcher. An unknown
venue's ordinary search check records offering-scoped evidence and opens one
deduplicated incident. The existing search Workflow owns checking and customer
communication; the support lane never sends email through agent tools.

A simulator `CourseOffering` owns rental source, public access, duration,
provider configuration and monitoring facts. Preserve the parent `Course`,
outdoor identity, customer intent and delivery state. Current real demand takes
priority over opted-in synthetic demand. Synthetic work retains its fixed
lifetime and suppressed transport.

The fixed lifetime ends the synthetic search, not the durable engineering
incident. The dispatcher can admit a distinct engineering incident authority
only from a positively consumed original synthetic simulator claim and its
validated current offering/source lineage. Historical alert references do not
authorize another scheduled search check, fixture extension or email. Unknown
provenance cannot turn an arbitrary inactive TEST into engineering work.

## Authoritative operating contracts

- [Scheduled parent](course-support-scheduled-parent.md): one actual preflight,
  its returned plan, a managed linked worktree and one supervised native launch.
- [Assigned simulator worker](simulator-support-assigned-worker.md): complete
  setup, owned commands, research guidance, implementation and release sequence.
- [Dispatcher](course-support-dispatcher.md): shared admission and ownership.
- [Failure register](course-support-simplification.md): evidence, corrections and
  acceptance gates.

The assigned worker contract replaces historical collector-specific recovery
recipes. Read the continuation contract only for an explicit returned
continuation handoff involving retained implementation or release provenance.
A stopped research-only chat is not permanent ownership.

## Durable execution and research

The source-bound public configuration lane supports TeeSheet tenant pages,
Upper Hand customer catalogs/details and the reviewed YourGolfBooking public
slot contract. The collector retains a typed configuration or a fixed contract
diagnostic; it does not persist raw API payloads. Owned workers can dry-run then
apply `configure --from-research` without a parent-prepared facts packet. The
newest complete observation, database clock, exact source and original ownership
remain authoritative. This is configuration discovery, not monitoring proof;
normal release, adoption and two distinct deployed verification checks still
govern closeout. See the assigned worker contract for the exact command flow.

Unclaimed startup and binding authority expire after fifteen minutes or a base
change. Database-time guards independently reject late binding and claiming.
A settled research-only hard failure closes that execution and schedules retry;
the normal planner also reconciles expired research after its bounded in-flight
request ends. Old identities, request attempts and diagnostics remain recorded.
A revoked executor cannot write, read again, recheck or recover.

Each observation retains the booking-source fingerprint actually checked.
Adoption preserves spent history and counters while clearing navigation; it
cannot relabel old failures as observations of the corrected source. Replacement
packets carry matching denied routes and sanitized failure diagnostics. They do
not forget the oldest route after four retries. Incomplete rendered pages retain
their original observation time, observed access controls, collector version,
warning and available configuration diagnostic. The current guide may offer the
same main route after sixty minutes under an unchanged version only for a
current-source rendered 2xx incomplete observation with positively empty access
controls. A repeat spends another one of the six reads and restarts the backoff
if incomplete again. Hard failures, HTTP denials, detected access controls and
unknown legacy evidence remain fenced.

Follow the current owned `researchGuide`; it determines permitted commands,
saved sources, indexed handoffs, budgets and retry priorities. Signed-out public
reads remain bounded by URL/DNS/access protection and provider coordination.
Never enter login, verification, a challenge, queue, checkout or a transaction.
Safe initial-document facts may survive a rejected stylesheet while
`renderComplete:false` and their provenance remain explicit. They do not prove
calendar availability. Missing historical fields remain unknown.

An already-owned worker may separately research official provider API reference
documentation with its available built-in search tool, within the assigned
contract's two-search/four-document limit. Queries exclude private identifiers
and opens exclude live venue, API, account and transaction pages. This
reference-only path cannot observe venue availability, execute a blocked POST,
reset source budgets or replace current owned venue evidence and verification.
Missing or ambiguous documentation remains unknown. All implementation and
release work retains the same original-owner gates.

Owned reads may also return ephemeral `publicSource.clientCodeEvidence` from
scripts already admitted during that same read. Bounded redacted excerpts are
inert untrusted reference evidence; names and routes do not prove server
semantics or authorize blocked methods. No new request, destination, credential,
source-budget or eligibility authority is granted. Raw excerpts stay outside
durable database history. Workers follow the assigned contract's privacy,
unknown-fact, reusable implementation and deployed verification gates.

Large admitted scripts and exhausted whole-source AST walks can return
`projection: TOKEN_WINDOW`. Every emitted token is independently redacted;
comments and literal data are removed. These windows are always marked
incomplete and never imply a complete function, program or API contract.
Identical redacted excerpts share one display slot, with bounded duplicate source locations retained for attribution. Matching text does not prove matching runtime behavior or authorize a request. Distinct complete scopes and incomplete token windows remain separate evidence; the existing four-excerpt and character limits still apply.
Source size, token/time scan, output and context bounds retain explicit
warnings. Omitted code stays unknown, and the projection grants no additional
network, method, destination, lease, eligibility or verification authority.

The same four-context/10,000-character code limit samples one context per
candidate source before additional contexts from a single source. Bounded
`candidateSourceHashes` and `sourceCoverageTruncated` distinguish omitted
candidate sources from the returned sample. They cover sources that produced
candidate contexts, not every fetched script; absence remains unknown.
Incremental merges preserve this bounded coverage metadata. No source may be
reopened or extra request made solely because its context was omitted.

For an unknown provider's fresh, positively public but incomplete rendered
shell, retry may return the existing `booking_research_required` result with
`researchPurpose: PUBLIC_REFERENCE_ROOT`. Follow its already-allowed rendered
same-site root link before an unchanged retry. This is reference research,
never a booking role or eligibility decision. It consumes the original six-read
budget, happens at most once per assignment, and cannot reopen a denial or
override access, freshness, source, destination, ownership, lease or backoff
guards. Known providers retain their existing path. Configuration and monitoring
still require the normal reviewed facts, exact release and two deployed checks.
Provider reference/contact information does not establish this venue's identity,
access, booking method or technical disposition.

Production command displays can be shorter than their complete results. The
worker runtime retains exact private stdout/stderr and a parsed complete JSON
payload, with a bounded receipt index. Workers inspect bounded fields from
their own verified capture instead of repeating protected operations. A legacy
zero-exit read-only inspection may be freshly inspected once through the
verified capture path after ordinary original-owner continuation admission;
this grants no wake, new owner, source read, lease extension or mutation replay.

Local tooling failures, transient provider backoff and positively observed
technical access restrictions require different outcomes. Inspect retained
diagnostics and repair reusable code when supported by evidence. Missing code,
an incomplete render, a marketing page, an empty occupied-inventory response,
booking-policy language or a future booking window cannot establish a final
technical restriction.

## Completion

Claim implementation paths before edits and retain fenced release provenance.
Register the owned committed candidate, verify its exact Ready Git production
deployment and both aliases, then use the normal queued recheck/progress flow.
Completion requires two distinct fresh successful simulator checks for the
current offering/source and exact release, without a newer failure.

For active-alert authority those are finished normal search checks. For explicit
engineering incident authority they are bounded independent observations from
the authenticated deployed verification route on that same exact release. They
retain their own request identities, source and provider timestamps and never
write search, match, customer probe or delivery rows. They prove engineering
coverage only. New engineering evidence records the selected reviewed duration
in both the version-two state and every reservation/observation. Both reads must
use that same duration. Legacy version-one evidence retains its original fixed
60-minute meaning. A check at another duration never changes or proves recovery
of an earlier customer's requested session length.

Real demand arriving during engineering verification requires
the normal customer lane, with safe original-owner closeout before yielding.

A launch, native turn, tests, HTTP200, deployment, prepared payload, provider
acceptance and inbox delivery are separate facts. Preserve honest retry when
monitoring remains incomplete; never manufacture availability or release proof.
