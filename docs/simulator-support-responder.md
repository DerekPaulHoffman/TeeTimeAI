# Simulator support in the existing responder

Simulator demand uses the sole ten-minute course-support dispatcher. It does not create another automation. A simulator `CourseOffering` owns rental source, public access, provider configuration, duration and monitoring facts; the parent `Course` and outdoor `CourseSupportIncident` stay unchanged.

The first unknown-venue search check reads the official public source, records an offering-scoped `NEEDS_ADAPTER` probe and opens one due-now `SimulatorSupportIncident`. The search workflow sends its normal bounded status communication. Repeated identical checks preserve the incident's episode and retry time. The support lane does not send customer or operator email itself.

Due real active future demand takes priority over explicitly opted-in `TEST` or `AUTOMATION` multi-cycle demand. Ordinary test searches do not enter the lane. Synthetic work retains its original classification, intent digest and native lifetime. An expired or withdrawn source leaves the incident open but cannot authorize a new worker. Later eligible demand can make the same offering actionable again.

## Owned simulator commands

The runtime wrapper permits `automation:simulator-support` alongside the existing course support, dispatch and deployment commands. It retains the same absolute Node/npm, verified Vercel package, production environment and native/project/checkout guards.

`claim` requires a clean named task branch at exact current `origin/main`, the bound native child, unchanged incident/source, due time and latest offering-scoped failure probe. Its private packet provides venue name, address, official website and source facts for investigation. It never treats an unverified rental as public.

All subsequent mutations require `--assignment-ref`, `--token` and the most recently returned `--revision`. Each successful mutation renews a fifteen-minute lease and increments revision. Dry runs make no product writes and do not increment revision. The original assignment stays `RUNNING / CONSUMED` and occupies shared capacity until durable completion, retry or withdrawal; expiry alone cannot free its slot.
