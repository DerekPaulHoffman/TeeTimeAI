# Stagehand and Sol responder

The local supervisor keeps durable jobs and immutable first-pickup/deadline
timestamps in Postgres. Stagehand finds an official-linked public source;
existing deterministic readers learn and independently replay the method.
Only backend-owned verification can activate an immutable recipe. Subsequent
checks execute that recipe without model calls. Normal search workflows,
canonical matching, deduplication and the email outbox retain delivery ownership.

Source-only navigation executes an already observed public anchor through
Playwright input on the same launch-owned, guarded Chrome target. The private
controller rechecks its document and element immediately before input; Stagehand
does not make another model request to re-plan that click. Request limits and
transaction guards remain in force. A provider club gateway is routing only.
An automatic same-document route requires native frame/loader continuity and a
completed public document read. Independent inspection must observe that route
again and reopen its exact URL before inspecting the adapter. Neither a model's
reported URL nor a history event establishes identity or availability.

An exact official `tee-time-reservations` landing captioned "Reserve a Tee
Time" is public document navigation. It grants no selected-time action, form
submission, query, login or checkout. Observed ForeUP facility bootstrap links,
including the provider's `booking/index/<id>` spelling, can go directly to fixed
inspection; their public configuration and inventory still require full proof.
Legacy CPS bookmarks must open their actually observed current tenant document.
An SDK destination alone cannot establish that route: fresh native source and
landing captures must corroborate the executed public anchor. No tenant is
inferred from the bookmark's club slug. CPS build `26.3.1.40424176516` has its
own reviewed anonymous-session and complete unpaged-day protocol; neighboring
builds remain unsupported until reviewed.

Fixed CPS inspection can capture its exact public source as a completed native
document without waiting for the general browser to render an anonymous app.
It retains one eight-second document-read wait tied to that document's time
origin and the original deadline. The typed CPS reader owns anonymous startup;
no general POST permission, rendered identity or availability is inferred from
an empty app shell. Both independent inventory challenges remain required.

ForeUP's literal "Online Booking" class is Standard Public only when its
catalog explicitly disables protection, booking blocks and deletion, and
requires no pass. Absent flags and member/pass variants remain unverified.
The complete catalog digest and every independent replay retain those checks.

Public Teesnap outdoor methods can use the existing fixed reader when the
canonical official URL is already the same HTTPS tenant root as the booking
source. The controller selects this fixed public-root transport before starting
a source browser or model. Its private helper performs one bounded source read,
closes, and then uses the ordinary backend challenges and activation path.
Inspection binds the full venue name, physical address, canonical
timezone and public course catalog. Each independent replay refreshes those
facts before one fixed, credentialless day request with bound date and players.
Held sections, booking joins and every returned row must be complete before an
empty result is accepted. A changed catalog, ambiguous identity, partial day or
unknown booking window remains incomplete. Marketing-site delegation is outside
this reader's current scope; recipes cannot supply arbitrary routes or code.

The generic model receives a compact reference-based copy of the recipe schema.
Only descriptive annotations and repeated schema text are removed; the actual
server validator, permitted actions, independent replay and token ceilings do
not change. Unsupported schema reference scopes retain their original clone.

An official ForeUP facility link may omit the selected schedule. A separately
marked compact-contact proof can bind that observed facility anchor to one
public schedule from the fresh provider catalog. It requires a unique canonical
root title, a sole fully printed physical contact with exact address and phone,
fresh raw/rendered agreement, and provider physical identity and timezone.
Ambiguous contacts or multiple qualifying public sheets remain unverified.
The recipe keeps the observed facility link and refreshes the complete proof on
every replay. Existing named-contact proofs retain their prior scope.

## Local worker modes

`COURSE_DISCOVERY_WORKER_MODE` is local operator configuration:

- `STAGEHAND_SOL` is the normal default. Source discovery uses the pinned
  Stagehand 4.3.0 SDK and GPT-6.1 Sol at medium reasoning through the current
  ChatGPT sign-in. No API-key or alternate-model fallback exists.
- `REUSE_ONLY` disables cold claims, model preparation and inference. Existing
  recipe executions retain their ordinary claim/result and cancellation checks.
  Use this mode for the restart/changed-parameter acceptance step.
- `NATIVE_SOL` explicitly selects the prior Sol worker for rollback. A failed
  Stagehand run never silently switches strategies or resets a clock.

The managed startup event records the validated handler's effective `workerMode`.
Keep that event and the new process identity in the restart receipt; a requested
environment value alone does not establish which mode actually started. The
private runtime configuration retains its existing three keys.

Source discovery receives ordinary public identity and alert parameters only.
It cannot provide times, executable actions, identity proofs or recipe metadata.
A bounded source-only checkpoint can resume trusted inspection on the one
automatic retry, using the same job, request, source fingerprint and original
deadlines. The fixed inspection and independent backend challenges stay fresh.
Incomplete reads never become an empty availability result.

Public source routing retains both the served document URL and its authenticated
History API route. Legacy public EZLinks links are investigation gateways, not
executable sources. Independent inspection must re-earn the exact tenant's
document/route binding in its fresh browser. A completed admitted native main
read can admit only its current same-origin history URL, without admitting the
whole redirected origin. Source evidence and progress clocks remain unchanged.

EZLinks public sponsor recipes pin an explicit public-title mode when the public
response omits the secondary rate catalog. Every returned row must belong to the
fresh master sponsor; member, resident, age-restricted and closed inventory stays
excluded. Whole venue names and a finite Championship/Par 3 layout suffix are
verified independently of physical layout preferences. Catalog changes invalidate
the saved method.

USchedule rentals without an Any Available resource option retain a bounded
immutable catalog of every public simulator resource. Replay uses a separate fresh
anonymous session for each resource and publishes slots only after all resources
complete. A changed catalog, failed bay or wrong date makes the entire check
incomplete. Only the exact visible provider no-times result proves an empty bay;
missing markup never proves absence. These engineering checks do not substitute
for cold-alert delivery and model-disabled restart acceptance.

The standard USchedule simulator pricing witness supports both the original
sidebar and the fluid responsive layout. The latter requires separate columns
for the selected service and party controls, dated inventory, and contact
information. The pricing card must remain in the service column, visible and
free of controls. Duplicate, contradictory or hidden pricing never establishes
a public per-bay rental.

Modern Teesnap metadata can default to cart-on while explicitly offering the
cart-off mode used by the reader. Both the published default and the complete
supported-mode catalog remain pinned in the saved hash. Missing cart-off support,
an unsupported default or a later catalog change still invalidates execution.

Generic fallback stops immediately when the trusted browser reports a finite
native transport fatality. It does not send that dead browser back to the model
or automatically spend a second attempt on it. Each generic attempt also allows
at most sixteen tool operations, 128,000 total recorded tokens, 32,000 uncached
input tokens and 8,192 output tokens. Usage updates replace cumulative totals;
cached input and reasoning output are subsets, not additional charges. A
threshold is enforced when usage is reported, so an in-flight response can
overshoot it. Budget exhaustion is terminal for that job; original failed jobs
and deadlines are preserved. This bounds investigation rather than claiming a
provider access restriction or empty inventory.

The operation limit covers public category, product, overview and calendar
transitions as well as recipe documentation and proposal. The token ceilings,
original job deadline, request limits and independent replay stay unchanged.
ForeUP's explicit seasonal Public Play labels use the same Standard Public
inventory scope; Member and Preferred Player labels remain excluded.

The isolated browser can load the observed public Swift catalogue and undated
single-bay overview through to its availability calendar. Exact Next/facility
metadata reads and the catalogue's same-query trailing-slash 308 remain
ancillary, never source or inventory proof. Its signed-out price/calendar GETs
may retain the literal null bearer plus zero-valued Clerk timestamp markers;
real bearer/session cookies remain excluded. This is transport evidence only:
complete product coverage, date-bound independent replay and alert delivery
are still required before a Swift method can activate.

A failed execution retains a previously verified immutable method when its
current source, identity and hash still agree. It opens one repair job based on
that exact version while normal executions can retry the method with fresh
verification. An exhausted repair does not erase the method or open another
model investigation for the same alert generation. Failed reads cannot produce
matches; a later successful read must pass the ordinary current-source, search,
identity, date, capacity, duration and completeness checks. Source changes and
invalid method bindings retain their existing invalidation behavior. Historical
failures and their original deadlines remain failed even if monitoring recovers.

Ordinary outdoor alerts cover standard Public inventory. Member, Preferred Player
and other qualified programs are outside that scope unless trusted eligibility is
available. Newly learned ForeUP methods declare `STANDARD_PUBLIC_CLASS_V1` and
save the bounded public catalog digest. Inspection and every later execution
re-read the current Public class, sheet and catalog before availability. Unknown
alternative classes on that selected sheet do not broaden the declared scope;
unresolved other sheets, malformed catalogs, duplicate Public classes and stale
identifiers still fail. Existing unscoped methods retain their original checks.

Ordinary ForeUP Course checks also verify the current Public class from a fresh,
bounded public catalog before requesting times. Saved schedule, class and
sheet-specific booking links must agree with that catalog. An unresolved scope
or conflicting response remains a failed course check; it cannot become an
empty result or a matching email. Verified times use the current Public booking
link, and the check does not rewrite saved Course metadata.

A clean fixed-inspection configuration failure can restart investigation from the
fresh official root within the original clock. That repair accepts only an
existing-adapter recipe backed by a new, matching typed inspection; browser,
JSON and HTTP recipes cannot bypass the failed typed identity or inventory gate.
Normal independent challenges and backend activation remain mandatory.

Outdoor checks verify enough golfer spots. Simulator checks verify one continuous
public rental resource for the requested duration and local window; an unstated
golfer limit remains `null`, rather than becoming a one-golfer restriction. A
saved, independently verified published golfer maximum is still freshly checked
and enforced. The provider's bay quantity remains one regardless of the alert's
golfer count. Mailbox correlation uses the same distinction and never treats a
bay count as proof of golfer capacity.

The Stagehand browser connects to a private, owned and guarded local browser
context. Its loopback endpoint stays inside the trusted host/driver boundary;
it is absent from model input, public evidence, logs and recipes. Provider reads
retain the existing public request policy and global/family coordination. The
installed Tee Time Spot Local Reader and the user's Chrome profile are not
modified. Authentication, interactive challenges and transaction flows remain
unresolved outcomes rather than reasons to weaken the reader's controls.

## Bounded public source navigation

Before another model extraction, the controller can propose the one strict
supported public source found in two stable, current native document captures.
The URL, document, loader, visibility and original deadline remain bound.
Ambiguous choices, stale captures or overflowing link/frame lists retain the
existing Stagehand/Sol path. This shortcut supplies routing only; it cannot
activate a method or provide identity or availability proof. Earlier model calls
still count, and a native decision does not invent a model extraction result.

Fresh visible links can establish an unverified routing candidate before a
click. Source discovery can also choose at most two freshly observed visible
iframe URLs from an exact enum and open each as the main document in the same
guarded target. Native parent-frame and loader checks run immediately before
navigation. Hidden, stale, foreign and `srcdoc` frames are rejected; ordinary
subframe networking remains denied. Repeated unchanged anchor navigation is
rejected. These observations confer no venue, availability or method proof.

Before extraction, the source controller waits for its current owned main
document to finish parsing and acknowledge its successful public response.
Each wait is bounded by 30 seconds and the shared 240-second source allowance,
measured from the immutable first pickup across both allowed attempts.
Ancillary pending reads do not require network idle. Fragment-only navigation
can reuse that same document; its path, query, target and loader stay bound.
An unparsed document cannot become an explicit unresolved model conclusion.

The fixed reader recognizes visible, untitled USchedule embeds through the same
strict public tenant grammar as its adapter. Both supported USchedule origins
retain the exact observed origin throughout source, session and availability
reads, and share one provider mutex. The finite duration-choice catalog permits
20 public options; requested duration, public rental selection, one-bay quantity,
date verification and request/body budgets remain independently enforced.

Source GET XHR/fetch responses use the existing 16 MB script allocation. Other
data/documents retain 2 MB, stylesheets 6 MB, aggregate decoded resources 48 MB,
the native tunnel 24 MB, and CDP messages 32 MB. The existing 192-request limit,
two global/one-family request coordination remain unchanged. The source
allowance is 240 seconds from the original first pickup, clipped by the existing
work deadline; it is never restarted per attempt. A valid owned initial source pause without a
Network ID is denied with a confirmed, bounded `Fetch.failRequest` ACK before
any admission or data use; unrelated source DOM may remain usable. All other
native readers retain fatal missing-ID handling. Abort failures, malformed or
duplicate events, unknown responses and expired ownership remain fatal.

An exactly attested cross-host script or stylesheet redirect is denied without
closing unrelated documents and data requests. The parent response, Location,
method, frame, network identity and resource kind must still match; the denied
asset is never released or treated as availability evidence. Bad provenance or
an unacknowledged denial remains fatal.

Failure checkpoints retain closed, bounded source and fixed-inspection facts
bound to the same job, request, source fingerprint, attempt and original clocks.
Optional diagnostics may be omitted with an explicit flag and digest to preserve
the source reference within 32 KB. They never restore source or method authority.
Recorded completed model usage is a lower bound when a call fails partway.

A current, closed Stagehand model-turn failure classified as service overload,
or `responseTooManyFailedAttempts` with explicit HTTP 429, delays only the existing
second job attempt by up to 45 seconds. The owned lease and heartbeats remain
live; cancellation and original deadlines still win. This performs no internal
generation retry, changes no model/action/resource cap and infers no account
quota state. A cooldown that exhausts the shared source allowance ends without
queuing a second source run. The four-minute source ceiling leaves less time
for inspection and delivery than the prior two-minute ceiling, but keeps the
original 12-minute work and 15-minute absolute job limits.

The TeeItUp physical-contact path can verify a named public contact block using
its complete raw and computed-visible address, scoped telephone and exact title
name. It does not require a WordPress brand link or an exact marketing heading.
When the official homepage delegates through a first-party booking page, the
optional `bookingEntryUrl` records that exact first edge separately from the
provider URL. The existing maximum-two-hop native chain must agree with it.
The second and final edge can use the exact requested public TeeItUp iframe
source when the original native parent capture proves its raw and computed-visible
source together. Hidden, form-contained, `srcdoc`, stale, overflowing or ambiguous
frame evidence is rejected. This does not permit child-frame browsing or confer
identity or availability authority on a serialized frame observation.
Provider identity remains unique, and every challenge and warm execution
rebuilds the contact and all observed links. Missing, conflicting, stale or
serialized evidence cannot substitute for that current native verification.

## Admission and rollout

`COURSE_DISCOVERY_ENABLED=true` is required. The absence of
`COURSE_DISCOVERY_ROLLOUT_MODE` retains the existing bounded pilot; `PILOT`
explicitly chooses that behavior. Pilot owner, three targets, cohort and normal
search-creation enrollment remain unchanged. No general admission is inferred
from missing or malformed pilot configuration.

`COURSE_DISCOVERY_ROLLOUT_MODE=GENERAL` explicitly enables normal real-demand
searches after acceptance. Synthetic/automation traffic stays excluded. Existing
adapters and supported installed-reader paths keep their established routes.
Legacy engineering ownership must be preserved; unresolved targets must not be
stranded between the two responders. Pilot receipts and evidence remain stored.

Disabling `COURSE_DISCOVERY_ENABLED` stops new admission and saved-recipe
selection without deleting customer demand, recipes or evidence. Keep the
managed worker's activation receipt bound to its actual clean deployed commit;
stop it before changing the runtime checkout. Reuse the existing managed task
and recovery supervisor rather than creating duplicate scheduled monitors.

After the managed worker and its owned children have drained, update dependencies
with `npm ci` and then run `npx prisma generate` in that maintained checkout.
Require successful generated-client import readiness from the same clean
checkout before cold claims. Readiness verifies the generated exports without
constructing `PrismaClient` or making a database request; missing or stub exports
fail with `LOCAL_GENERATED_PRISMA_CLIENT_UNAVAILABLE`. Installed dependencies
alone are insufficient. This safeguard is not a diagnosis of an earlier pilot
failure, and it never changes a job's original clocks or authority.

## Acceptance receipt

Before opening a new cohort, verify the production deployment and managed worker
against the frozen source version, then verify the exact pilot owner, target keys
and run identifier. Pilot selector changes require a fresh Git deployment so the
application reads the new environment snapshot. Arm the read-only observer before
the first normal alert submission; neither an earlier deployment nor a running
worker proves that the next cohort can enter discovery.

Passing tests or deploying this code does not prove acceptance. Record the
random selection process and every exclusion; independently confirm public
inventory without supplying worker routes or configuration. Create three
ordinary alerts only after readiness, then permit no source hints, manual job
claims/retries, configuration changes or completion commands during cold
learning. Preserve first pickup, original deadline, attempts, activated hashes,
independent replay evidence, canonical times, normal outbox acceptance and
matching mailbox timestamps. Require all three to receive matching alerts
within 15 minutes of their original pickup, with a five-minute target.

Restart the worker in `REUSE_ONLY`, change ordinary alert parameters and verify
fresh matching evidence from the same saved methods, zero discovery/model calls
and no duplicate already-sent match IDs. Report exact application/SDK/CLI
versions, elapsed times, recorded token usage and unproved limitations. Expand
to GENERAL only after these checks and the cancellation/failure/duplicate
checks pass.
