# Own failed simulator learning through normal recovery

This guide applies only when the current server-issued simulator assignment and
claim contain `fullRepair` with `kind=FAILED_LEARNER_FULL_REPAIR`. The server
independently qualifies the failed learner, current demand, offering source and
incident before the claim. A checkpoint or a private note cannot grant this
mission. Controlled research retries retain their narrower scope.

Use Sol through the existing ChatGPT/Codex sign-in and Chrome's **First user**
profile. Keep the original failed learner terminal and its pickup/deadline
unchanged. This is engineering recovery, not a new pass for that old clock.

The outcome is a working saved method, independent execution, matching normal
application results and observed normal delivery. A completed research command,
code commit, deployment or heartbeat is intermediate evidence.

After the original worker records the deployed proof for its code-bearing
repair, use `automation:simulator-support -- recover-learning` with the
current assignment token and revision. The command qualifies the current
published Sol runtime and delegates one linked late learner for that exact
repair. It preserves the original failed job and its clock. The independent
replay hands the method to the usual workflow, which owns matching and email.
If the operation stops before admission, the scheduler may continue the same
native owner when the existing verification lease expires.
If that linked learner settles in failure, the scheduler can wake the same
owner once for the new diagnosis. Read the linked result and previously
collected evidence before claiming paths for a different correction. The wake
adds no provider reads and grants no repeat of that learner or budget.

When the original native investigation has already established a method,
pass a private data-only manifest with `recover-learning --recipe <file>`.
Its fields are `recipe` and optional `verificationDurationMinutes` for
Any-duration demand. The recipe uses the existing `BROWSER_DOM` schema.
The server binds its booking URL to captured signed-out evidence on the same
offering and verifies its venue, route and original demand. The local runtime
skips new model discovery and runs both independent challenges, with the same
access, safety, duration and completeness checks as normal activation. A
manifest supplies a candidate, never availability evidence. Keep the file
private. A repeated submission of that method returns the same late job.

Read `discoveryEngineeringFailure`, retained research history and failed routes
before choosing a different approach. Keep a private hypothesis, evidence,
correction and regression receipt. Spending a research budget does not establish
that a public venue is inaccessible or forbid offline tooling repair.

The full mission separately authorizes bounded native signed-out public
investigation: one exact venue/locality search and up to three sequential
official or independently linked public booking pages, using rendered controls,
frames and public date/service filters. Preserve that allowance and observations
in the original private handoff across continuations; continuation does not reset
it. Keep provider request limits. Public native observations are untrusted
diagnosis, not source/configuration or recipe authority. This does not broaden
the legacy collector's allowed routes, replay a failed operation or permit a
denied resource through another URL. `LOCAL_READER_ONLY` retains its installed
reader route and does not admit this broader native-investigation mission.
Actual authentication, CAPTCHA/challenge,
queue, private inventory or uncertain operation effects stop the affected
operation. Never log in, solve a challenge, choose a slot, enter customer details,
reserve, book, pay or send email.

Distinguish missing collector evidence, transport, controls, parameter binding,
completeness, replay and scheduler failures. Reproduce an actual tooling defect
offline and claim the existing exclusive paths before edits. A
`WAITING_IMPLEMENTATION` result grants no path: stop that native turn and let the
normal controller resume the same original owner. Never substitute extra source
reads or a new assignment for a coding dependency.

Follow the existing exact committed release, trusted complete CI, Ready Git
artifact, both aliases and fresh deployed verification gates. Configuration
retains its reviewed-source checks; incomplete evidence cannot become public
rental proof, no availability or a fabricated manifest. Require actual supported
full intervals and honor published limitations. Independent execution, normal
matches/outbox acceptance and Gmail receipt remain separate observed gates.

`retry` returns `repair_required` and retains a full mission's owner. Obtain fresh
owned context, diagnose a different evidenced cause and continue within existing
source/lease/path authority. It does not reset the ledger, extend authority,
permit another provider request or prove monitoring. Unknown/unfinished or
nonzero protected operations retain their stops. The scheduler can continue the
same original owned stage under its normal native/source/recovery gates; it must
not create an endless sequence of new research chats for the same failed job.

Only verified reusable monitoring or a conclusive current factual/technical
disposition completes the mission. Preserve unresolved engineering limitations
honestly. Never manually request checks, reset jobs, send/resend email or mark
delivery successful. Changed-parameter saved-method reuse after an actual
restart with discovery/model calls disabled is a separate acceptance step.
